# GetSenderId Telegram Bot

Небольшой Telegram-бот: принимает пересланное сообщение и возвращает доступный Telegram ID пользователя или канала.

## Граница анонимности

- бот обрабатывает update в памяти и не имеет базы сообщений или пользовательской аналитики;
- непересланные сообщения игнорируются;
- текст сообщений, Telegram ID, usernames и chat metadata не отправляются;
- ошибки Telegram записываются только по типу исключения, без текста исключения и транспортных подробностей.

## Настройка

Токен передаётся только через переменную окружения:

```powershell
$env:GETSENDERID_TGBOT_TOKEN = "<bot token>"
dotnet run --project GetSenderId_TgBot
```

`Secret.cs` больше не требуется.

## Работа в трее

Приложение запускается скрытым и сразу помещает значок в область уведомлений Windows.

- двойной щелчок по значку или пункт `Открыть` показывает окно состояния;
- кнопка сворачивания и крестик скрывают окно обратно в трей, не останавливая бота;
- пункт `Выход` в меню значка корректно останавливает Telegram polling и завершает процесс;
- команда ServerPanel `stop` также завершает процесс, а не просто скрывает окно.

Для диагностики окно можно показать сразу флагом `--show`; без него запуск всегда скрытый.

## ServerPanel

Клиент включён по умолчанию и использует только loopback API:

```text
http://127.0.0.1:5088
```

Постоянный host ID: `get-sender-id-tgbot`. Каждые пять секунд отправляются:

- имя процесса;
- окружение;
- используемая память;
- uptime;
- версия сборки;
- прикладной статус `Healthy`.

CPU, число сообщений, request rate, error rate и любые Telegram-поля намеренно не собираются: панели достаточно знать, жив ли процесс.

Команды применяются по закрытому списку:

| Команда | Поведение |
|---|---|
| `start` | Безопасный no-op: получивший команду процесс уже запущен |
| `stop` | Корректно отменяет polling и завершает процесс |
| `restart` | Запускает тот же доверенный `.exe`, затем завершает текущий процесс |

`restart` отклоняется при запуске через `dotnet run`, потому что в таком режиме текущим процессом является общий `dotnet.exe`, а не приложение.

ServerPanel выдаёт команды с семантикой at-most-once: после успешного `GET` команда считается доставленной и может быть потеряна, если процесс аварийно завершится до применения. API панели не следует выводить из loopback без TLS, аутентификации и отдельной модели прав.
